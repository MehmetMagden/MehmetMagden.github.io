2.3 Infrastructure as Code

All system components are automated via Ansible. The playbooks execute in a deterministic sequence:

  • 01_base_setup.yml – Kernel modules tuning, disable swap
  • 01_2_hostname_fix.yml – Set node hostnames
  • 01_5_network_fix.yml – Enable IPv4 Forwarding
  • 01_8_containerd_fix.yml – Configure Containerd
  • 02_install_k8s.yml – Install kubelet, kubeadm, kubectl
  • 03_master_init.yml – Initialize master node, deploy Flannel CNI
  • 04_workers_join.yml – Auto-join worker nodes to the cluster
  • 05_deploy_swisstask.yml – Deploy SwissTask API + PostgreSQL manifests
  • 06_deploy_monitoring.yml – Deploy Prometheus and Grafana via Helm

3. Deployment & Automation

3.1 DevSecOps CI/CD Pipeline

A push to the main branch triggers the GitHub Actions pipeline, which incorporates built-in security gates:

Push → Security Gates → Test → Build & Scan → Push to Docker Hub → Deploy ↓ ↓ ↓ ↓ ↓ ↓ Code Bandit/Flake8 pytest Docker/Trivy Git SHA Tag kubectl rollout (SAST/Lint) (SQLite) (Vuln. Check) (Immutable) (Rolling Update)

Key Feature: Images are not tagged with :latest, but rather with the unique Git Commit-SHA. This effectively prevents image caching issues and ensures deployments are 100% reproducible.

3.2 Rolling Updates

New versions are deployed via Kubernetes Rolling Updates to ensure high availability:

  • New pods are initialized with the updated image.
  • Health Checks (Liveness & Readiness Probes) verify readiness.
  • Old pods are gracefully terminated only after the new pods are fully operational.
  • Result: Zero-Downtime Deployments.

3.3 Self-Healing Mechanisms

Kubernetes autonomously monitors and maintains cluster health:

  • Pod Failures: If a pod crashes, the Kubelet automatically restarts it.
  • Node Failures: If a node becomes unresponsive, its pods are evicted and rescheduled on healthy nodes.

4. Engineering Challenges & Solutions

4.1 Kubelet Health-Check Collision (CrashLoopBackOff)

Problem: To protect against DDoS attacks, the API was secured with a strict rate limiter (50 requests/hour). The internal Kubernetes Kubelet service, which executes Liveness and Readiness probes every 10 seconds, quickly exceeded this limit, receiving HTTP 429 (Too Many Requests) errors. Consequently, Kubernetes falsely flagged completely healthy pods as "failing" and continuously terminated them, causing a severe CrashLoopBackOff.

Root Cause: The rate limiter failed to distinguish internal cluster health-check traffic from external, potentially malicious requests.

Solution: Analyzed the internal traffic routing and implemented targeted @limiter.exempt decorators explicitly for the internal probes:

@app.route('/health', methods=['GET'])
@limiter.exempt
def health_check():
    """Kubernetes liveness probe bypasses rate limits"""
    # ...

Result: Internal K8s monitoring functions seamlessly (0 Restarts), while all external API endpoints remain strictly protected against DDoS abuse.

4.2 Kubernetes Swap Issue

Problem: Worker nodes failed to start pods, returning the error: "cannot run on a system with swap enabled".

Root Cause: Kubernetes does not operate stably when Linux Swap is enabled, as the Kubelet service terminates itself to preserve memory allocation accuracy.

Solution: Permanently disabled swap across all nodes via Ansible automation:

- name: Disable swap
  shell: swapoff -a
- name: Remove from fstab
  lineinfile:
    path: /etc/fstab
    regexp: "^.* swap"
    state: absent

Result: The cluster operates stably, and pods are scheduled reliably.

4.3 Docker Image Caching

Problem: Following a successful CI/CD image rebuild, newly spawned pods continued executing the old application code.

Solution: Transitioned to an "Immutable Tags" strategy. Images are now strictly tagged with the unique Git Commit-SHA:

docker push myrepo/app:${{ github.sha }}

Result: Every deployment guarantees the extraction of the exact, updated code. Rollbacks are now deterministic and secure.
